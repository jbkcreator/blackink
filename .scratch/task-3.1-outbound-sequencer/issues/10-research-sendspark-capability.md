## Resolution

**Sendspark is fit for purpose. Touch 1 can be fully automated.** Real public
REST API at `https://api-gw.sendspark.com/v1`, auth via `x-api-key` +
`x-api-secret`.

The model is **record once, render N times**: a human records a single base
video per campaign; it is overlaid on each prospect's own website
(`backgroundUrl`, a static page render). Per prospect it is one POST. No
human-in-the-loop step is needed and Touch 1's content does not need
renegotiating.

The GIF requirement (§4.1) is satisfied outright — the API returns a hosted
`thumbnailUrl`, documented verbatim as the GIF preview, with explicit
guidance to pair it with `videoLink` for email embedding.

**Three consequences that change the design:**

1. **The audit score cannot go inside the video.** In-video dynamic variables
   are exactly three predefined ones — First Name, Company Name, Job Title.
   No custom or numeric variables. §4.1 assumes the score appears in the GIF;
   it must instead live in the email body or landing-page copy. Folded into
   ticket 11 as a spec conflict to escalate.
2. **Watch percentage is webhook-only — no polling fallback exists.** A
   dropped webhook means a permanently missing number, so 3.1.2's phone card
   (§11.3) and 3.1.3's reply card (§16) must tolerate null. Partial-watch
   reliability is unverified — see ticket 18.
3. **The bulk endpoint is mandatory at scale.** 30 req/min standard but only
   **1 req/min** on `/prospects/bulk`; a naive per-contact loop caps at
   30/min.

**Cost:** 1 credit per personalized minute per prospect. API and webhooks
require Growth ($99/mo, 250 min) or above; ~$0.145/prospect at a 30s video
after the included allowance.

**No account, credentials, or config key exist** — see ticket 17.

## Question

Touch 1 depends on Sendspark for four artifacts (§2.4, §4.1): a personalized
landing page / video URL, a video identifier, an animated GIF thumbnail
previewing the prospect's website and audit score, and a watch percentage.
The GIF must be visible in the email and linked to the landing page. The
watch percentage is also required on 3.1.2's phone card (§11.3) and 3.1.3's
reply card (§16).

There is **zero Sendspark code in the repo** — only a `{video_url}` merge tag
in `ALLOWED_TAGS` and some prompt text.

Establish from Sendspark's actual API documentation:

1. Is there a **public API**, and what does authentication look like?
2. Can a personalized video/landing page be **created programmatically** per
   prospect, with merge data (company name, audit score, website)? Or does
   it require a human to record and configure each one?
3. Is the **animated GIF thumbnail generated by Sendspark**, and is it
   retrievable as a hosted URL for embedding in an email? Can it be made to
   preview the prospect's own website, as §4.1 requires?
4. Is **watch percentage** exposed — polled via API, pushed via webhook, or
   both? What granularity, and what latency?
5. What is the **per-prospect cost and rate limit**? At scale this is one
   video asset per contact.
6. Does the account already exist? Are there credentials? (If provisioning
   is needed, that becomes a `wayfinder:task` ticket.)

The load-bearing question is **(2)**: if personalized videos cannot be
created programmatically, Touch 1 cannot be fully automated, and either the
sequencer gains a human-in-the-loop step or Touch 1's content is
renegotiated. Answer that one plainly.

## Research findings

Researched 2026-09-03 against live Sendspark docs. **Sendspark has a real public
REST API and Touch 1 can be automated.** No human is needed per prospect — but a
human must record **one** base video, once per campaign.

### 1. Public API + auth — YES

Base URL `https://api-gw.sendspark.com/v1`. Two credentials sent as headers on
every request: `x-api-key` (scoped to the **workspace**) and `x-api-secret`
(scoped to the **user profile**), plus `Accept: application/json`. Both minted in
the API Credentials tab of workspace settings. Health check at `GET /auth/health`.
- https://help.sendspark.com/en/articles/9051823-api-automatically-create-dynamic-videos-via-api
- https://help.sendspark.com/how-to-create-api-keys.md

Endpoints:

| Method | Path |
|---|---|
| POST | `/workspaces/{workspaceId}/dynamics` (create campaign) |
| GET | `/workspaces/{workspaceId}/dynamics` / `/{dynamicId}` |
| POST | `/workspaces/{workspaceId}/dynamics/{dynamicId}/prospect` |
| POST | `.../dynamics/{dynamicId}/prospects/bulk` |
| GET | `.../dynamics/{dynamicId}/prospects/{email}` |

### 2. Programmatic per-prospect creation — YES (the load-bearing answer)

Which world we are in: **the automatable one, with one caveat.** The model is
"record once, render N times". A human records a single base video per campaign;
that recording is identical for every prospect and is **overlaid on the
prospect's own website**. Thereafter each prospect is a single POST. Fields on
the prospect call: `contactName`, `contactEmail`, `company`, `jobTitle`,
`backgroundUrl`, `processAndAuthorizeCharge: true` (acknowledges over-plan
charges — must be `true` or the call is rejected at the limit).
- https://help.sendspark.com/getting-started-guide-dynamic-videos.md

**Caveat — audit score cannot go in the video.** In-video dynamic variables are
limited to three predefined ones: First Name, Company Name, Job Title (swapped by
AI voice clone at render). Arbitrary/numeric custom variables such as an audit
score are **not supported**. Score must be rendered in the email body / GIF
overlay / landing-page copy instead, not spoken or burned into the video.
- https://help.sendspark.com/multiple-variables-in-dynamic-videos.md

### 3. Animated GIF thumbnail — YES, hosted, previews prospect's site

Sendspark generates an animated GIF preview per prospect and exposes it as a
hosted URL. Three fields come back: `videoLink` (share/landing page),
`embedLink` (iframe embed), `thumbnailUrl` — documented verbatim as "the image
URL for the GIF preview of your video", with the explicit instruction to "use
this together with Video Link to embed your video in email with a GIF preview".
Exactly the §4.1 pattern.

`backgroundUrl` is "the URL for the webpage that you want to superimpose your
video over. Can be their website homepage, or any public URL." Note it renders as
a **static webpage background**, not a live screen recording. Sendspark can
auto-extract it from the prospect's email domain if omitted — but Blackink should
pass it explicitly from `companies.domain`.
- https://help.sendspark.com/en/articles/9163890-old-clay-how-to-create-ai-personalized-videos-in-clay-via-api

### 4. Watch percentage — webhook, not polling

Webhooks carry `watchPercentage`, documented as "the percentage of the video the
visitor watched before pausing, stopping, or finishing it", on the
Video-Watched-to-the-End event. Common payload properties: `campaignId`,
`dynamicCampaignId`, `contactInfo` (incl. `contactInfo.contactEmail` — the join
key back to `contacts`), `videoLink`, `embedLink`, `thumbnailUrl`, `workspaceId`,
`creatorId`. Other events: `video_generated_dv`, `video_mp4_ready`, Video Played,
Video CTA Clicked.
- https://help.sendspark.com/en/articles/10619230-webhooks-properties-included-in-sendspark-webhooks
- https://help.sendspark.com/en/articles/9186828-webhooks-an-introduction-to-webhooks-in-sendspark

**Two unresolved gaps — do not design around them until confirmed with vendor:**
(a) No documented GET analytics endpoint returning `watchPercentage`, so there is
**no polling fallback**; a dropped webhook means a permanently missing number.
3.1.2's phone card and 3.1.3's reply card must therefore tolerate a null watch %.
(b) Docs do not state webhook latency, nor whether a partial watch (e.g. 40%,
viewer never returns) fires an event at all — third-party sources claim only
"played" and "watched 100%" fire reliably. **Verify empirically before §11.3
depends on it.**

### 5. Cost and rate limits

Billing is **1 credit per personalized minute per prospect** — a 60s video for 50
leads burns 50 credits. The fallback video costs one extra minute, once per
campaign. Rate limits: **30 req/min** standard, **1 req/min** on
`/prospects/bulk` — bulk is the only sane path at scale; a naive per-contact loop
caps at 30/min.

Plans (API + webhooks require **Growth or above**): Solo $49/100 min; Growth
$99/250 min; Team $299/1,000 min; Business $699/3,000 min. Overage never cuts you
off: $0.39/$0.29/$0.24/$0.19 per minute by tier. At a 30s video, Growth ≈ 500
prospects/mo included, then ~$0.145 each.
- https://www.sendspark.com/pricing
- https://help.sendspark.com/what-are-dynamic-video-minutes-credits.md

### 6. Account / credentials

**Not established.** No Sendspark code, config key, or credential exists in the
repo. Provisioning a Growth+ workspace and storing `SENDSPARK_API_KEY` /
`SENDSPARK_API_SECRET` / `SENDSPARK_WORKSPACE_ID` via `get_settings()` should be
split out as a `wayfinder:task` ticket, along with recording the base video.

### Alternatives

Not needed — Sendspark is fit for purpose and is the strongest option in this
niche precisely because of the website-overlay + hosted-GIF combination. For the
record: Vidyard has a public API and GIF thumbnails but no per-prospect
website-overlay rendering; Potion is the closest true competitor (API-driven
personalized video, GIF thumbnails); Loom has an API but no personalization
merge; Bonjoro and Warmly are human-recorded / intent-signal tools and do not
generate per-prospect video programmatically.
